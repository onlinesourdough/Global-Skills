The `v0.2.0` tag does not exist during Build. These notes describe the candidate
that must pass lead Review before an explicitly authorized Ship.

- Release all four canonical skills: `clarify`, `manage-skills`,
  `orchestrate-workers`, and `shape-offer`.
- Align the Codex plugin, repository marketplace, pinned Skills CLI commands,
  validation, rollback guidance, and candidate/post-Ship evidence boundary.
- Add the MIT License plus concise contribution, private security-reporting,
  and public support guidance.
- Replace private pilot wording with public installation, scope, provenance,
  Skills Atlas, recovery, and release documentation.
- Record the intended post-Ship Atlas contract: bounded anonymous GitHub API
  reads in public static mode, observed revision/access display, read-only
  behavior, and a one-edit/new-branch/pull-request boundary for optional
  authenticated self-hosting.
- Expand secret scanning to the working tree and every blob reachable from
  local refs without printing matched values.
- Remove stale three-skill visual assets from the current release tree and
  label example business data as synthetic.
- Sanitize the two ordinary branch refs in place to one reviewed clean-root
  candidate while keeping `onlinesourdough/Skills` as the only canonical
  endpoint. The repository remains private pending GitHub Support purge and a
  private-state re-audit; no rename, archive, replacement, or duplicate
  repository is permitted.
- Withhold historical `v0.1.0` continuity by deleting its private release and
  tag without replacement. `v0.2.0` is the first planned public release.

Post-Ship public verification must confirm that `v0.2.0` resolves to the
reviewed release commit, both pinned install paths discover the four skills,
installed bytes match the tag, and no public `v0.1.0` tag or release exists at
the same canonical endpoint.
